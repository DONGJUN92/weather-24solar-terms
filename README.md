# Weather24 — 절기의 약속 검증소

> **2026 기상·기후 AI 해커톤 경진대회** 출품작
> 24절기라는 조상의 '계절 약속'이 내 지역에서 아직 유효한지, 기상청 실측 자료로 학습자가 직접 검증하는 체험형 기후 교육 웹앱

**🔗 구동 URL — <https://weather-24solar-terms.vercel.app/>**
로그인·설치·결제 없이 크롬에서 즉시 조작 가능 · 모바일 지원

## 1. 무엇을 배우는가

중학교 3학년 ~ 고등학교 2학년 학습자가 다음 네 가지를 **수행으로** 익힙니다.

| 학습목표 | 학습자가 할 수 있게 되는 것 |
|---|---|
| ① 절기 ≠ 기후 | 24절기가 태양 위치로 정한 천문 날짜임을 설명하고, 그 무렵 관측된 기온 변화와 구분할 수 있다 |
| ② 자료의 범위 | 한 지점·5년 자료로 말할 수 있는 것과 없는 것을 구분해 결론의 범위를 좁힐 수 있다 |
| ③ 기준을 정의 | ‘덥다’·‘여름’·‘비가 많다’ 같은 모호한 말을 임계값으로 정의하고, 기준을 바꾸면 결론이 달라짐을 설명할 수 있다 |
| ④ 근거만큼 결론 | 주장·근거·추론·**한계**(CERL)를 갖춘 한 문장을 스스로 작성할 수 있다 |

### 핵심 체험 — 기준선 하나

화면의 보라색 **‘덥다’ 기준선**을 학습자가 직접 정합니다(드래그 · 슬라이더 · ± 스테퍼 · 의미 있는 프리셋).
정하는 즉시 차트 바로 위의 숫자가 바뀝니다.

```
조작 (기준선)  →  즉시 반응 (더위일 · 더위가 그치는 날)  →  판정 (CERL 4요소)  →  재도전
```

### 학습 동선 (핵심 12분 / 전체 45~55분)

미션 하나는 **핵심 2분 + 선택 심화**로 나뉩니다. 핵심만 하면 5미션 약 12분,
심화와 자유탐구까지 하면 45~55분입니다. 수업 시간에 맞춰 교사가 자를 수 있습니다.

| 단계 | 내용 | 핵심 | 심화 포함 |
|---|---|---|---|
| 🌍 24절기 입문 *(선택)* | 지구 공전 궤도 위 24절기 · 한자 풀이 · 왜 조상들이 만들었나 · “여름은 태양에 가까워서 덥다” 오개념 교정 | — | 5분 |
| 미션 1 · 처서 | 처서의 약속은 아직 유효한가 (서울, 기온) | 2분 | 8분 |
| 미션 2 · 여름 길이 | ‘여름’을 몇 도로 정의하느냐에 따라 길이가 달라진다 | 2분 | 8분 |
| 미션 3 · 지역 비교 | 제주 vs 강원(춘천) — 한 지역 결과를 전국으로 넓힐 수 있는가 | 2분 | 8분 |
| 미션 4 · 강수 강도 | **비 온 날은 줄었는데 큰비는 늘었다** — 같은 자료, 반대 결론 | 2분 | 8분 |
| 미션 5 · 계절 지연 | **가장 더운 날은 하지가 아니라 40일 뒤** — 절기가 어긋나 보이는 이유는 기후변화 하나가 아니다 | 2분 | 8분 |
| 완료 | 내 기록(복사·인쇄) · 고향 기후 카드 PNG · 🌍 지구 CO₂ 맥락 | — | 6분 |
| 자유탐구 | 16지역 × 24절기 × 3지표 조합 · **16지점 지도** · **비교 기간 26창** · 탐구 질문 · 기상청 기준표 · 링크 공유 | — | 자유 |

#### 조작 변수 3축 (Mo1 p.29 “변수 2~3개”)

| 축 | 조작 | 어디서 |
|---|---|---|
| **세로 — 기준값** | ‘덥다’를 몇 도로 정할지 슬라이더·드래그 | 미션 1~4 · 자유탐구 |
| **가로 — 날짜** | 가장 더울 것 같은 날을 직접 찍기 | 미션 5 |
| **기간 — 비교 창** | ‘현재’로 쓸 5년을 26가지 중에서 선택 | 자유탐구 |

여기에 **지역**(16지점 지도 클릭)과 **지표**(기온·습도·강수) 선택이 더해집니다.

교사용 인쇄물: [`prototype/교사_학습지.html`](prototype/교사_학습지.html) — 수업 흐름 · 활동지 · 오개념표 · 평가 루브릭(6점) · 2022 개정 성취기준 연결

## 2. 구동 환경 · 배포 방법

### 필요 환경
- **사용자**: 최신 크롬(또는 Edge·Safari). 별도 설치 없음
- **개발/재빌드**: Python 3.10+ (`pandas`, `numpy`, `requests`), Node.js 18+ (검증 스크립트용)
- **배포**: Vercel (정적 파일 + 서버리스 함수 1개)

### 로컬에서 실행
```bash
# 저장소 루트에서 정적 서버를 띄운다 (web_data/ 접근이 필요하므로 루트에서)
python -m http.server 8777
# 브라우저에서 http://localhost:8777/prototype/index.html
```
> 로컬에서는 `/api/ai-turn`이 없으므로 AI 감사관은 **규칙 기반 점검으로 자동 대체**됩니다. 학습 동선은 100% 동작합니다.

### 배포 (Vercel)
```bash
vercel --prod
```
- 라우팅은 [`vercel.json`](vercel.json)이 처리합니다(`/` → `prototype/index.html`, `/web_data/*`, `/api/*`).
- **환경변수**(Vercel → Settings → Environment Variables):

| 변수 | 필수 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | 선택 | AI 증거 감사관용. **없어도 앱은 정상 동작**하며 규칙 기반 점검으로 대체됩니다 |
| `OPENAI_MODEL` | 선택 | 기본값 `gpt-5.4-mini` |

> ⚠️ 키는 **환경변수에만** 둡니다. 저장소·클라이언트 번들·배포 산출물 어디에도 키가 없습니다(§5 참조).

### 데이터 재빌드
```bash
# 1) 원시 수집 (기상청 API 키 필요 — 아래 참조)
set KMA_SERVICE_KEY=발급받은_키          # Windows
export KMA_SERVICE_KEY=발급받은_키       # bash
cd data_collectors && python collect_kma_allyears.py

# 2) 가공 + 회귀 검증 (실패 시 exit 1)
cd ../processing
python build_solar_terms.py      # → prototype/solar_terms_data.js, web_data/solar_terms_climatology.json
python verify_solar_terms.py     # 4,810개 assert
```

`KMA_SERVICE_KEY`는 [공공데이터포털](https://www.data.go.kr) 또는 [기상청 API 허브](https://apihub.kma.go.kr)에서
**본인 계정으로 발급**받아 환경변수로 지정합니다. 발급 절차: [`data_collectors/API_KEY_발급_가이드.md`](data_collectors/API_KEY_발급_가이드.md)

## 4. 생성형 AI 활용

### 결과물 제작 과정에서의 활용
개발 전 과정을 **Claude Code**로 진행했습니다. 프롬프트 세션 기록과 방법론은
[`AI_활용_기록.md`](AI_활용_기록.md)에 정리했습니다(제출물 ④).

요약: 32개 커밋 · 데이터 파이프라인 설계 → 앱 구현 → **AI 레드팀 자체 감사(3라운드 44건)** → 전량 수정 → 프로덕션 검증.
특히 레드팀 단계에서 **AI가 자기 결과물의 과학적 오류를 잡아내고 수치로 반증**한 과정이 이 프로젝트의 AI 활용 핵심입니다.

### 결과물 안에서의 AI
`/api/ai-turn` — **증거 감사관**. 학습자가 쓴 판정문에서 과장·범위 이탈·인과 단정을 짚습니다.

- 결론을 **대신 쓰지 않습니다.** 감사 입력창은 비어 있고, 예시 문장을 그대로 두면 요청을 거부합니다.
- 화면에 표시된 증거 카드 범위 안에서만 답하도록 시스템 지침과 JSON 스키마(strict)로 강제합니다.
- **AI가 실패해도 학습이 끊기지 않습니다** — 규칙 기반 점검(정규식 6종)이 같은 항목을 즉시 확인합니다.
- 품질 검증: 한국어 학습자 답안 100케이스 평가셋에서 **96/100**, 잘 쓴 답을 잘못 지적한 **오탐 0건**
  (재현: `node eval_harness.js` · 데이터 `eval_set.json`)

## 7. 과학적 무결성 — 이 앱이 스스로 지키는 약속

교육용이라도 수치를 부풀리지 않기 위해 다음을 코드와 검증 게이트로 강제합니다.

1. **일수는 곡선이 아니라 실측에서 센다.** 화면의 ‘더위일’은 연도별 실제 관측값으로 세어 평균한 값입니다.
   보기용 평활 곡선에서 세면 고임계에서 과소·저임계에서 과대해지므로 쓰지 않습니다.
2. **불완결 연도를 섞지 않는다.** 관측 350일 미만 연도는 평년 비교에서 제외하고(2026년 등),
   지점별로 실제 사용한 연도 수를 화면에 표기합니다.
3. **자기 자료의 흔들림을 공개한다.** “5년 창을 옮기면 시차가 +4~+17일에서 움직이고, 30년으로 보면 +10일”을
   판정문의 한계 절과 방법론 서랍에 함께 적습니다.
4. **상관을 인과로 말하지 않는다.** CO₂–기온 그래프에 r²를 보여주되, 원인을 말하려면 다른 종류의 증거가
   필요하다는 사실을 같은 화면에서 밝힙니다.
5. **계산할 수 없는 것은 없다고 말한다.** 자료에 일평균만 있으므로 열대야(최저)·폭염(최고)은
   “이 화면에서 계산할 수 없다”고 명시하고, 해당 프리셋을 비활성으로 둡니다.
6. **모든 화면에 출처·표본 수·계산 방법·한계**를 ‘이 숫자는 어떻게 나왔나’ 서랍으로 제공합니다.
